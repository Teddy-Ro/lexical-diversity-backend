# Author texts Backend — лабораторная работа №3

## ЛР-3: REST API

Ветка: `lab3-author_texts-api`. HTML второй лабораторной сохранён по `/author_texts`.
Новый API расположен по `/api`, документация — `/api/docs`, схема — `/api/openapi.json`.
Регистрация работает, вход/выход пока заглушки без cookie; настоящие сессии Redis — ЛР-4.

| Метод | URL после `/api` | Назначение |
| --- | --- | --- |
| GET | `/author_texts?min_text_length=5` | Опубликованные тексты, фильтр на сервере |
| GET | `/author_texts/feed` | Первая опубликованная карточка |
| GET | `/author_texts/{author_text_id}?next=true` | Карточка по ID, с next — следующая |
| GET | `/author_texts/draft` | Черновик текущего пользователя, ID не передаётся |
| POST | `/author_texts` | Создание черновика: multipart название, фото, видео |
| PUT | `/author_texts/{author_text_id}/publish` | Заполнение и публикация собственного черновика |
| DELETE | `/author_texts/{author_text_id}` | Логическое удаление своего опубликованного текста |
| POST | `/author_texts/{author_text_id}/like` | JSON `{"value":1}` — поставить, `{"value":0}` — снять |
| POST | `/author_texts_users/register` | JSON username/password, регистрация |
| POST | `/author_texts_users/login` | Заглушка ЛР-3 |
| POST | `/author_texts_users/logout` | Заглушка ЛР-3 |

Это 10 логических операций из задания: два URL ленты обслуживает одна функция.
Пустая лента или отсутствующий черновик дают 404; пустой корпус — `[]`.
Последняя карточка по `next=true` переходит к первой опубликованной.

### Формат данных

Ответ карточки имеет постоянный набор полей, включая `null`: author_text_id,
work_title, author_name, publication_year, short_description, text_content,
author_texts_image_url, author_texts_video_url, unique_token_count, text_length,
author_texts_ratio, author_texts_like_count. Он одинаков для черновика и публикации.
HTTP-код, статус draft/published/deleted и пароль в JSON не включаются.
Успех — 200/201, удаление и заглушки — 200 с пустым телом.
Ошибки тоже без тела: 404 — не найдено/не свой текст, 409 — повторный черновик
или логин, 422 — неправильные входные данные, 503 — недоступен MinIO.

POST создания принимает ровно три multipart-поля: `work_title`,
`author_texts_image`, `author_texts_video`. Фото JPEG/PNG/WebP до 10 МиБ,
видео MP4/WebM до 50 МиБ. Проверяются MIME, размер и сигнатура заголовка;
полная декодируемость и длительность не проверяются. Для сдачи выберите короткий ролик.
В новых строках БД сохраняются ключи `author_texts_<uuid>.<ext>`, в API — URL.
Старые URL из ЛР-2 поддерживаются без перезаписи данных.
При ошибке второго файла или сохранения БД уже загруженные файлы удаляются.
При логическом удалении карточки её файлы и строка БД остаются.

PUT принимает только `work_title`, `author_name`, `publication_year` (nullable),
`short_description`, `text_content`. В соответствии с выбранной темой оба показателя
вычисляются из текста, а не вводятся вручную. Это адаптация общего требования
методички о заполнении двух тематических полей. Неизвестные/системные поля запрещены.

### Где смотреть код для защиты

- `api/author_texts_api.py` — маршруты, сериализация HTTP, пустые ошибки.
- `api/author_texts_dependencies.py` — singleton с константным пользователем 1.
- `schemas/author_texts_schemas.py` — входные/выходные схемы Pydantic.
- `services/author_texts_service.py` — статусы, владелец, лайки, регистрация.
- `repositories/author_texts_repository.py` — ORM-фильтр и выбор одной карточки.
- `services/author_texts_media.py` — MinIO и имена файлов.
- `services/author_texts_statistics.py` — токенизация и TTR.
- `models/author_texts_models.py` — три модели и ограничения БД.

Подсчёт лайков: `len(author_text.likes)` в `serialize_author_texts`.
Коллекция заранее загружается через `selectinload`, повторный лайк не создаёт новую связь.
Для ЛР-4 меняется зависимость текущего пользователя; бизнес-методы уже получают его ID.
Старые SSR-методы не являются защищённым API: перед эксплуатацией с настоящей
авторизацией их изменяющие маршруты нужно закрыть или отключить.

### Тестирование ЛР-3

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
$env:AUTHOR_TEXTS_RUN_DB_TESTS='1'
$env:AUTHOR_TEXTS_RUN_MINIO_TESTS='1'
.venv/Scripts/python.exe -m unittest discover -s tests -p 'author_texts_test*.py' -v
```

Тестовые строки PostgreSQL откатываются транзакцией, тест MinIO удаляет только
два созданных им объекта. Последовательности ID могут увеличиться.
Если Docker недоступен, можно проверить API изолированно:

```powershell
$env:AUTHOR_TEXTS_RUN_DB_TESTS='0'
$env:AUTHOR_TEXTS_RUN_MINIO_TESTS='0'
$env:AUTHOR_TEXTS_TEST_SQLITE='1'
.venv/Scripts/python.exe -m unittest discover -s tests -p 'author_texts_test*.py' -v
```

SQLite используется только для тестов в памяти; он не заменяет PostgreSQL приложения
и не проверяет блокировки PostgreSQL или настоящую загрузку в MinIO.

## Сохранённая часть ЛР-2: запуск и инфраструктура

FastAPI-приложение для расчёта лексического разнообразия авторских текстов.
Данные хранятся в PostgreSQL, запросы выполняются асинхронно через SQLAlchemy
и `asyncpg`, структура БД управляется Alembic.

## Быстрый запуск в Docker

Выберите один способ запуска backend: целиком в Docker или локально через
`python author_texts_main.py`. Одновременно использовать оба способа не нужно, поскольку
оба занимают порт `8000`.

```powershell
docker compose --profile full up -d --build
```

- приложение: <http://127.0.0.1:8000/author_texts>;
- Adminer: <http://127.0.0.1:8080>;
- MinIO: <http://127.0.0.1:9001>.

PostgreSQL внутри Docker работает на `5432`, а на Windows опубликован через
`55432`, чтобы не конфликтовать с локальной установкой PostgreSQL.

Данные для входа в Adminer:

```text
Система: PostgreSQL
Сервер: ttr-postgres
Пользователь: author_texts_user
Пароль: ttr_password
База данных: author_texts_database
```

При запуске backend-контейнер сам применяет миграции и один раз добавляет
демонстрационные данные.

## Локальный запуск backend

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
docker compose up -d ttr-postgres ttr-adminer ttr-minio ttr-minio-seed
python -m alembic upgrade head
python -m data.author_texts_seed
python author_texts_main.py
```

При локальном запуске приложение доступно на <http://127.0.0.1:8000>.

## Модель данных

- `author_texts_users` — пользователи и создатели текстов;
- `author_texts` — тексты со статусами `draft`, `published`, `deleted`;
- `author_texts_text_likes` — связь многие-ко-многим пользователей и текстов.

На одного пользователя допускается только один черновик. Каскадное удаление
не используется. Количество токенов, уникальных токенов и TTR вычисляются из
введённого текста без учёта регистра. Новые фото и видео в ЛР-2 не сохраняются.
В `author_texts_users.password_hash` хранится хеш пароля, не исходный пароль.
У новых демонстрационных пользователей пароль `author_texts_demo`; у ранее
созданных пользователей при миграции установлен случайный неизвестный пароль.
Авторизация в ЛР-2 не реализуется.

## Добавление и стандартные медиа

До «Далее» доступны только название и две отдельные кнопки выбора видео и фото.
Файлы можно выбрать на устройстве, но они намеренно не отправляются и не сохраняются.
«Далее» создаёт черновик; обновление страницы само по себе ничего не создаёт.
После «Далее» пользователь заполняет автора, необязательный год, описание и текст.
Публикация рассчитывает `text_length` и `unique_token_count` из текста автоматически.
Остальные поля до публикации допускают `NULL`, потому что черновик ещё не заполнен.

Резервные фото и видео лежат в `public/media` frontend и отдаются SSR-сервером
по `/author_texts-assets/media/author_texts_default.jpg` и `.webm`.
Они подставляются, если соответствующее поле медиа пустое. Собственные медиа
демонстрационных карточек по-прежнему находятся в MinIO.
Имя bucket — `author-texts-media`: S3/MinIO не допускает подчёркивания в именах bucket.
JavaScript в шаблонах нет: фильтр отправляется обычной GET-формой.

## Где считаются лайки

В `api/author_texts_handlers.py`, функция `prepare_author_texts_text`:
`len(author_texts_text.likes)`. Связанные строки загружаются через
`selectinload(AuthorText.likes)`, число передаётся в шаблон как
`author_texts_like_count`. Сердце пока только отображает это число.

## Шесть HTTP-методов ЛР-2

- `GET /author_texts` — корпус и фильтрация по длине;
- `GET /author_texts/add` — форма нового текста или существующего черновика;
- `GET /author_texts/{author_text_id}` — опубликованный текст в ленте;
- `POST /author_texts/drafts` — создание черновика по кнопке «Далее» через ORM;
- `POST /author_texts/{author_text_id}/publish` — публикация через ORM;
- `POST /author_texts/{author_text_id}/delete` — логическое удаление сырым SQL `UPDATE`.

БД называется `author_texts_database`, роль подключения — `author_texts_user`.
Пароль при переименовании не изменялся. Исторические миграции и инфраструктурные
контейнеры/тома сохраняют старый префикс для совместимости с существующими данными.
Таблицы приложения и HTTP-адреса используют `author_texts`.
Перед миграцией требуется резервная копия; удалённые служебные
даты `created_at`/`published_at` можно восстановить только из неё.

ER-диаграмма и перечень скриншотов находятся в каталоге `docs`.
